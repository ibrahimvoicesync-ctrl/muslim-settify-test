## Planning notes

**Why the production regression check needs no Vercel access.** RESEARCH.md assumption A4 flagged that `settifyowtp.com` and `settifyhaqqan.com` are invisible to this session's Vercel account, and worried this made BRAND-03's no-regression requirement uncheckable here. That concern dissolves on inspection: the requirement is about observable redirect behavior, and redirect behavior is readable over plain public HTTP by anyone. Task 3 checks all four brands with unauthenticated requests. Vercel dashboard visibility is needed only to *change* those projects, which this phase explicitly must not do.

**Why regression risk is structurally near-zero, and why we still check.** The three existing brands deploy from their own Vercel Projects tracking their own branches. Plan 01-01's change landed on `main`, and plan 01-02 created a separate project tracking `h-muslimsettify`. Nothing in this phase pushes to, redeploys, or reconfigures the existing brands' projects, so their live bundles are untouched. The regression surface is therefore confined to the source-level conditional chain, which plan 01-01 already covered with five local host-header probes. Task 3's production check is confirmation of that reasoning against reality, not the primary defence — but it is cheap and it is the only step that would catch a wrong assumption about which project serves which domain.

**Flagged assumption, still open.** RESEARCH.md assumption A1 holds that `h.muslimsettify.com` is a subdomain of the existing `muslimsettify.com` zone rather than a separate registration. The entire DNS approach in this plan — one additive CNAME on an existing zone — depends on that. If Task 1's `vercel domains inspect` output instead indicates a domain requiring nameserver delegation or apex A records, stop and re-plan the DNS step rather than improvising.

**Human-verify mode is `end-of-phase`,** so browser confirmation appears as a `<human-check>` inside Task 3's verify block rather than as a `checkpoint:human-verify` task. The registrar step remains a `checkpoint:human-action` because it genuinely has no CLI path available to this session.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local CLI session to Vercel account API | `vercel domains` commands cross this boundary and can mutate domain-to-project bindings for live production brands |
| Vercel to external DNS registrar | The CNAME record is created outside both git and Vercel, in a system neither can validate ahead of time |
| Public internet to the new subdomain | Once DNS resolves, `h.muslimsettify.com` is publicly reachable for the first time, while still serving a placeholder Typeform target |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Tampering | `vercel domains add --force` | high | mitigate | `--force` detaches a domain from whatever project currently serves it before reattaching. Applied to a live brand domain this is an immediate outage. Mitigated by an explicit prohibition, by an acceptance criterion asserting no `--force` invocation, and by instructing the executor to treat an "already attached" failure as a finding to surface rather than an obstacle to override. |
| T-01-12 | Tampering | Domain argument passed to `vercel domains add` | high | mitigate | Passing the apex `muslimsettify.com` instead of the subdomain would repoint the parent brand's live traffic to the new project serving a placeholder form. Mitigated by specifying the exact hostname string in the action, by an acceptance criterion asserting the apex remains associated with its original project after the command, and by the absence of `--force`, which means an accidental apex attach fails rather than silently succeeding. |
| T-01-13 | Tampering | Guessed CNAME target at the registrar | medium | mitigate | A guessed generic target leaves the domain in Pending indefinitely, with no error surfaced anywhere in the codebase or build. Mitigated by requiring the value be read from `vercel domains inspect` for this specific domain and project pair, and verified by a `dig` acceptance criterion matching the captured value. |
| T-01-14 | Denial of Service | Editing or removing existing records on the `muslimsettify.com` zone | high | mitigate | The zone serves the live parent brand. An edited or deleted record there is a production outage for a brand this phase is supposed to leave alone. Mitigated by scoping Task 2 to an additive record only, stating that constraint explicitly in the human-action instructions, and confirming in the acceptance criteria that no pre-existing record was changed. |
| T-01-03 | Information Disclosure | Placeholder Typeform URL now publicly reachable | medium | mitigate | This plan is the moment the placeholder becomes internet-facing. The value is deliberately non-resolving and self-describing, so a visitor who follows it sees a Typeform not-found page rather than a plausible-looking wrong form, and no data can be captured or misrouted. The residual risk is organizational: the subdomain must not be advertised or used in ad campaigns until Phase 3 swaps in the real form ID. Carried as an explicit prohibition and surfaced in the human-check instructions so the user sees the placeholder behavior firsthand rather than reading about it. |
| T-01-15 | Spoofing | Host header spoofing against the new public subdomain | low | accept | Same posture as T-01-01 in plan 01-01: resolution selects among fixed hardcoded constants and never constructs a target from the header, so a spoofed host cannot produce an attacker-controlled redirect. Already an accepted, documented risk in `.planning/codebase/CONCERNS.md`. Adding a 4th allow-listed host does not widen it. |
| T-01-SC | Tampering | npm / pip / cargo installs | high | accept | This plan performs zero package-manager installs and touches no source files; `package.json` and the lockfile are unchanged. No Package Legitimacy Audit applies and no legitimacy checkpoint is required. |
