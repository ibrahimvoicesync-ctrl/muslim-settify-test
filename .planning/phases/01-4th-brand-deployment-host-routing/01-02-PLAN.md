## Planning notes

**Why this plan is gated.** RESEARCH.md Open Questions 1 and 2 surfaced a real, unresolved account-visibility gap during live CLI inspection: the authenticated Vercel account (`ibrahim-7482`) can see two teams, and `muslimsettify.com` is visible under `generista`, but **neither `settifyowtp.com` nor `settifyhaqqan.com` appears under either team**. Separately, this repo's git remote (`ibrahimvoicesync-ctrl/muslim-settify-test`) matches a project name under the *personal* team, not `generista`. Either those two brand domains live in a Vercel account this session cannot reach, or this checkout is a sandbox copy distinct from what actually serves production. Both readings are plausible and they lead to different correct actions. Guessing here risks creating the project under the wrong team (requiring a transfer) or, worse, deploying against a repo that is not the production one. Task 1 resolves this before any platform mutation occurs.

**Human-verify mode is `end-of-phase`,** so this plan uses a `checkpoint:decision` (a genuine directional choice, not a confirmation of Claude's work) and a `checkpoint:human-action` (a dashboard-only setting with no CLI equivalent). Browser-based confirmation of the finished result is deferred to plan 01-03's `<human-check>`.

**CLI freshness caveat.** RESEARCH.md marks its Vercel CLI command specifics as valid for roughly 7 days, since Vercel's CLI surface shifts. If any flag below is rejected by the installed CLI (55.0.0), run the relevant `--help` and adapt, rather than falling back to an interactive prompt the executor cannot answer or guessing at an alternative subcommand.
