Declare, in this order:

1. `export const ATTRIBUTION_ALLOWLIST` — an array of exactly these six lowercase string literals in this exact order, with an `as const` assertion: utm_source, utm_medium, utm_campaign, utm_content, utm_term, referrer. These six keys are locked by D-03 and their spelling must match TYPE-02's Typeform Hidden Field names exactly, including the double-r in `referrer` (D-04). Export it so Phase 3 can reference the canonical field-name list rather than retyping it.

2. `const MAX_ATTRIBUTION_VALUE_LENGTH = 500` — module-private. This is a discretionary hardening addition the planner is taking under CONTEXT.md's "Claude's Discretion" for this module's internals, answering RESEARCH.md Open Question 1: it serves ATTR-04's locked "the redirect must never break" guarantee by bounding how long the outbound `Location` header can grow when an ad platform emits a malformed multi-kilobyte macro value. It is not a scope reduction — no realistic attribution value is affected.

3. `type SearchParamsInput = { [key: string]: string | string[] | undefined }` — module-private; this is the shape Next.js resolves a `searchParams` prop to.

4. `function clampValue(value: string): string` — module-private; returns the value truncated to `MAX_ATTRIBUTION_VALUE_LENGTH` characters.

5. `function firstValue(v: string | string[] | undefined): string | undefined` — module-private. Take element `[0]` when the input is an array (Next.js gives an array for a repeated key), otherwise take the value as-is. Then return `clampValue(...)` of it when it is truthy, and `undefined` when it is not. Use a truthy test, not an `in` check and not a `!== undefined` check — a truthy test is what collapses the empty string, `undefined`, and a missing key into one identical "omit this" outcome, which is exactly what ATTR-04 requires (RESEARCH.md Pitfall 3).

6. `export function filterAttributionParams(source: SearchParamsInput): URLSearchParams` — construct an empty `URLSearchParams`, then iterate `ATTRIBUTION_ALLOWLIST` and, for each key, call `firstValue(source[key])` and `.set(key, value)` only when the result is truthy. Iterate the allowlist, never the source object — do not use `Object.entries`, do not spread `source` into the `URLSearchParams` constructor, do not add a "copy everything else" branch. Iterating the fixed allowlist is what makes ATTR-05 structurally true instead of merely intended.

7. `export function buildAttributionQuery(source: SearchParamsInput, referer: string | null): string` — call `filterAttributionParams(source)`, then, when `referer` is truthy, `.set("referrer", clampValue(referer))` on the result. Note the deliberate ordering: the header-derived value is written after the filter pass, so a real HTTP header wins over an attacker-supplied `?referrer=` in the incoming query string. Then `.toString()` the params and return the empty string when that is empty, otherwise the string prefixed with a single `?`. Returning `""` (not `"?"`) for the empty case is load-bearing — plan 02-02 interpolates this directly after the literal `/apply`, and a bare `?` would produce a cosmetically broken link.

8. `export function appendAttributionParams(baseUrl: string, params: URLSearchParams): string` — when `params` has zero keys, return `baseUrl` unchanged, by identity, without parsing it. Otherwise construct `new URL(baseUrl)`, `.set(key, value)` each entry onto `url.searchParams`, and return `url.toString()`. Never concatenate values into the URL string by hand: `.set()` percent-encodes, which is what prevents a UTM value containing `&`, `#`, a space, or a control character from restructuring or injecting into the outbound `Location` header.

Do not include any example Typeform form link in this file's code or comments — the prebuild guard `scripts/check-no-direct-typeform.mjs` walks `lib/` and fails the build if it finds the form host followed by a `/to/` path anywhere outside `app/apply/page.tsx`. Use `example.com` in any illustrative comment, or omit the example.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Next.js server (`/apply` query string) | Fully attacker-controllable input; anyone can craft any key/value and hit this route directly |
| Next.js server → Typeform (outbound `Location` header) | Untrusted-derived data leaves this system and is persisted in a third-party Results table |
| `resolveTypeformUrl` host map → redirect destination | Server-controlled trust anchor; must remain the sole selector of the destination |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `app/apply/page.tsx` outbound Location | high | mitigate | `filterAttributionParams` iterates the fixed six-key `ATTRIBUTION_ALLOWLIST`, never the caller's object — no unlisted key (internal params, accidental PII, session-ish values) can reach Typeform's stored responses. Proven by Task 3 probe P1 (`foo` absent). |
| T-02-02 | Tampering | Outbound `Location` header construction | high | mitigate | URL assembled only via `new URL()` + `url.searchParams.set()`, which percent-encodes; no string concatenation of raw values anywhere. Blocks `&`/`#`/space/control-character injection restructuring the redirect. Proven by Task 1 encoding assertion and Task 3 probe P4. |
| T-02-03 | Denial of Service | Oversized attribution value inflating the `Location` header past proxy/browser URL limits, breaking the redirect (violating ATTR-04) | medium | mitigate | `clampValue` truncates every value to `MAX_ATTRIBUTION_VALUE_LENGTH` = 500 before it is `.set()`. Proven by the 600-character clamp assertion in Task 1. |
| T-02-04 | Spoofing | Attacker-crafted `utm_*` / `referrer` values on `/apply` | low | accept | Inherent to marketing attribution on any public site (RESEARCH.md Security Domain). The allowlist protects the *structure* of the outbound redirect; validating the *truthfulness* of attribution values is explicitly out of scope for v1 and no requirement asserts it. |
| T-02-05 | Tampering | Open redirect via user-controlled destination | low | mitigate | The destination is chosen solely by `resolveTypeformUrl`'s hardcoded host map (unchanged Phase 1 code). `url.searchParams.set()` cannot alter origin, host, or path, so appended params are structurally incapable of retargeting the redirect. Proven by Task 3 probe P5 (four hosts still map to their own bases). |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | RESEARCH.md's Package Legitimacy Audit records zero packages for this phase; every primitive used is a runtime global or an existing dependency. Gate: `git diff --name-only -- package.json package-lock.json` must produce no output in every task. No `[ASSUMED]`/`[SUS]` package exists, so no legitimacy checkpoint is required. |
