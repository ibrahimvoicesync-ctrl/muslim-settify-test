<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Next.js server (`/` and `/more-success` query strings) | Fully attacker-controllable input; anyone can craft any key/value on a landing URL |
| browser → Next.js server (`Referer` request header) | Attacker-controllable input; a request can carry any referer value, and browsers additionally trim it per their referrer policy |
| Next.js server → rendered HTML (`<a href>` attribute values) | Untrusted-derived data is interpolated into markup served to every visitor |
| Rendered href → `/apply` → Typeform | Untrusted-derived data continues out of the system and is persisted third-party |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Information Disclosure | Rendered Apply hrefs on `/` and `/more-success` | high | mitigate | `buildAttributionQuery` applies the same six-key `ATTRIBUTION_ALLOWLIST` at capture time, so a non-allowlisted landing param never reaches the DOM at all — the allowlist is enforced at both ends, not only at the redirect. Proven by Probe A (`foo` absent from every href) and Probe D. |
| T-02-07 | Tampering | Attribution value interpolated into an `<a href>` attribute | medium | mitigate | Three layers: values are percent-encoded by `URLSearchParams.toString()` before they leave `lib/attribution.ts`; the href is set through a JSX attribute so React HTML-escapes it (no `dangerouslySetInnerHTML`); and the href always begins with the fixed literal path `/apply`, so no value can prepend a `javascript:` or absolute-URL scheme. Proven by Probe C's fully-encoded referrer value. |
| T-02-08 | Information Disclosure | Full landing-page `Referer` URL forwarded into Typeform's stored responses | medium | accept | The `Referer` header is the source REQUIREMENTS.md (ATTR-01) and D-04 specify for the `referrer` hidden field; browsers already apply their own referrer policy (`strict-origin-when-cross-origin` by default sends origin only on cross-origin navigations), and the value is clamped to 500 characters by plan 02-01's `clampValue`. No redaction beyond that is specified by any locked requirement; adding one would be unrequested scope. ASVS L1 requires no further control here. |
| T-02-09 | Denial of Service | `/` and `/more-success` lose static prerendering and are server-rendered per request | low | accept | Intentional and unavoidable: the `Referer` header is only readable server-side, so request-time capture necessarily opts these routes into dynamic rendering (RESEARCH.md Pitfall 4). Documented as the expected build-output change and recorded in the SUMMARY so a later review does not misdiagnose it. |
| T-02-10 | Information Disclosure | External Telegram link on `/more-success` | low | mitigate | `applyQuery` is passed only to `Navbar` and `ApplyCTA`; the third-party `AnimatedButton` href is left literally unchanged, so no marketing params leak to an unrelated destination. Proven by Probe E's Telegram-href count of exactly 1. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | RESEARCH.md's Package Legitimacy Audit records zero packages for this phase; no `[ASSUMED]`/`[SUS]` entry exists, so no legitimacy checkpoint is required. Gate: `git diff --name-only -- package.json package-lock.json` must produce no output in every task. |
</threat_model>
